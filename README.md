# ESP-Car: ESP32-C3 + DRV8833 + два мотора N90

Прошивка подключается к вашему роутеру в режиме Wi-Fi Station (2,4 ГГц).
Интернет не нужен, телефон/ноутбук должны быть в той же локальной сети.

## Подключение

| ESP32-C3 | DRV8833 |
| --- | --- |
| GPIO21 | AIN1 |
| GPIO20 | AIN2 |
| GPIO10 | BIN1 |
| GPIO9 | BIN2 |
| GND | GND |

Мотор A → AO1/AO2, мотор B → BO1/BO2. В коде A считается левым колесом,
B — правым. Это именно номера GPIO, а не порядковые номера контактов платы.

VM/VIN драйвера подключите к питанию моторов, подходящему их номинальному напряжению;
у DRV8833 рабочий диапазон 2,7–10,8 В. По обозначению N90 нельзя определить
номинальное напряжение и ток: проверьте параметры ваших моторов, включая ток заклинивания.
Не питайте моторы от 3V3 ESP32. Земля ESP32, драйвера и источника моторов должна быть общей.
Если на модуле есть nSLEEP/SLP, он должен быть в HIGH (3,3 В); проверьте,
есть ли на конкретном модуле штатная подтяжка. При LOW мосты отключены.

**Особенности выбранных выводов:**

- GPIO9 — загрузочный вывод (BOOT). Внешняя схема не должна удерживать его в LOW
  при обычном включении. Если плата не загружается с драйвером, временно отключите
  провод GPIO9–BIN2; устойчивое решение — перенести BIN2 на свободный GPIO,
  изменив `B_IN2` в коде. Не добавляйте подтяжку GPIO9 к земле.
- GPIO20/21 — также RX/TX UART0. Логи Serial направлены во встроенный USB CDC, но ROM может выдавать
  импульсы на TX при старте. На платах с USB–UART мостом GPIO20 может быть занят
  выходом этого моста: проверьте схему платы; для такой платы лучше перенести
  входы мотора A на свободные GPIO.
- При прошивке и сбросе отключайте питание моторов. Программа не контролирует
  выводы до запуска `setup()`. Для аппаратного запрета движения на старте нужен
  отдельный управляемый nSLEEP с подтяжкой вниз и соответствующее изменение кода.

## Загрузка через VS Code / PlatformIO

1. Откройте эту папку в VS Code с расширением **PlatformIO IDE**.
2. Подключите ESP32-C3 USB-кабелем с передачей данных. Питание моторов пока отключено.
3. Нажмите **PlatformIO: Build** (галочка), затем **PlatformIO: Upload** (стрелка).
4. Если загрузчик не отвечает: удерживайте **BOOT**, нажмите и отпустите **RESET/EN**,
   отпустите **BOOT**, повторите Upload. Если RESET нет, подключите USB при зажатой BOOT.
5. После прошивки нажмите RESET/EN без BOOT для обычного запуска.

Выбран профиль `esp32-c3-devkitm-1`, Arduino, 4 МБ flash — обычная конфигурация
ESP32-C3. Точная модель вашей платы не указана. Если её flash/USB-схема отличается,
потребуется подобрать профиль. Исходный профиль Adafruit QT Py заменён, поскольку
принадлежность платы к этой модели не подтверждена.

Через терминал **PlatformIO Core CLI** команды такие:

```sh
pio run
pio device list
pio run --target upload
```

Если порт не определяется автоматически:

```sh
pio run --target upload --upload-port /dev/cu.usbmodemXXXX
```

На macOS используйте фактический `/dev/cu.*` из `pio device list`.
Если `pio` отсутствует в PATH, используйте терминал PlatformIO или
`~/.platformio/penv/bin/pio` вместо `pio`.

## Управление

1. Скопируйте `include/secrets.example.h` в `include/secrets.h` и укажите
   в нём `WIFI_SSID` и `WIFI_PASSWORD` вашей сети 2,4 ГГц.
   Файл `include/secrets.h` исключён из Git; не добавляйте его в коммиты.
2. Загрузите прошивку, откройте Monitor на 115200. Дождитесь подключения к роутеру
   и строки `[HTTP] Server started: http://.../`. IP назначается роутером через DHCP.
3. Подключите телефон/ноутбук к той же локальной сети и откройте HTTP-адрес из лога.
   Старый адрес `192.168.4.1` больше не используется. Имя сети ESP-Car в списке Wi-Fi
   не появится. Телефон может быть на 5 ГГц того же роутера, если обе сети объединены
   в одну LAN. Гостевая сеть и изоляция клиентов могут блокировать доступ к плате.
4. При первом тесте поднимите колёса над поверхностью и включите питание моторов.
5. Отклоните стик вверх/вниз для движения или влево/вправо для разворота на месте.
   Направление выбирается по большей оси отклонения; в центре — зона остановки.
   Отпускание стика или кнопка **СТОП** отключает подачу мощности.
   В режиме фиксации выбранное направление сохраняется после отпускания.
   Скорость меняется ползунком; начальное значение — 60%.

Также работают стрелки клавиатуры; пробел останавливает моторы.
При потере фокуса/скрытии страницы браузер отправляет команду остановки.
Во время удержания команды повторяются каждые 100 мс. Независимая задача ESP32
снимает мощность после 450 мс без новой корректной команды (проверка каждые 20 мс),
в том числе если обработчик HTTP занят. Это программная защита, не аппаратный аварийный стоп.
Остановка — свободный выбег: колёса могут продолжать вращаться по инерции.
Открывайте одну вкладку управления: команды из нескольких вкладок/устройств
будут конкурировать. При обрыве Wi-Fi моторы отключаются; подключение восстанавливается
автоматически с повторной попыткой каждые 15 секунд. После восстановления движения
сами не возобновляются без новых команд. Адрес DHCP может измениться — смотрите лог.

Если колесо крутится в противоположную сторону, выключите питание и поменяйте
провода этого мотора местами либо установите `INVERT_A` / `INVERT_B` в `true`
в `src/main.cpp` и загрузите прошивку снова. Если левый/правый повороты перепутаны,
проверьте, что A — левое колесо, B — правое.

## Просмотр логов

После загрузки откройте **PlatformIO → Monitor** или выполните:

```sh
pio device monitor --baud 115200
```

При необходимости укажите `--port /dev/cu.usbmodemXXXX`. После включения USB CDC
порт может измениться — проверьте `pio device list` заново.

Логи передаются через **встроенный USB Serial/JTAG ESP32-C3 (GPIO18/19)**.
Разъём, подключённый только через CH340/CP210x к UART0, эти логи не покажет.
Не переключайте Serial на UART0 при текущей распиновке моторов GPIO20/21.

В логе есть причина сброса, SSID роутера, состояние подключения, причина обрыва,
полученный IP, URL сервера, сила сигнала RSSI, запрос страницы, изменения направления/скорости,
некорректные команды и остановка по таймауту. Повторяющиеся команды удержания
не засоряют лог. Пароль не печатается. Каждые 10 секунд и при подключении
USB-монитора повторяются адрес страницы и состояние сети; поэтому можно открыть
монитор уже после запуска. При заполнении буфера сообщения пропускаются,
чтобы диагностика не задерживала управление моторами.

Если подключение не удаётся, проверьте SSID/пароль, наличие сети 2,4 ГГц и сигнал
рядом с роутером. Строки `network not found`, `connection failed` и числовой
`reason` в логе помогут диагностике. Смена AP на Station сама по себе не устраняет
возможную аппаратную проблему антенны.

## ESP32-C3: AUTH_EXPIRE и мощность Wi-Fi

После `WiFi.begin()` применяется `WiFi.setTxPower(WIFI_POWER_8_5dBm)`.
Этот обходной способ описан для некоторых плат ESP32-C3 в
[arduino-esp32 #6551](https://github.com/espressif/arduino-esp32/issues/6551):
при стандартной мощности встречаются ошибки авторизации и невидимая AP.
Это не подтверждает аппаратную причину именно вашей неисправности и может уменьшить дальность.
В логе печатается фактическая настройка `TX=8.50 dBm`, прочитанная через `getTxPower()`;
мощность хранится в единицах 0,25 dBm. Настройку можно изменить в `WIFI_TX_POWER`.
Причины обрыва теперь расшифровываются: 2 — AUTH_EXPIRE, 202 — AUTH_FAIL,
205 — CONNECTION_FAIL. Сами эти коды не доказывают неправильный пароль.

## Страница открывается, но моторы не вращаются

После отдельной проверки Wi-Fi верните четыре сигнальных провода драйвера,
общую землю и подходящее питание VM. USB ESP32 сам по себе не питает моторы.
Если модуль имеет SLP/nSLEEP, проверьте, что он разрешает работу (HIGH 3,3 В).

Поднимите колёса и удерживайте ▲. При 60% в Monitor ожидается:

```text
[MOTOR] forward 60% | A GPIO21=153 GPIO20=0 | B GPIO10=153 GPIO9=0
```

Это диагностические значения 0–255: для промежуточной мощности читается LEDC,
на 0%/100% — логический уровень GPIO. Это не измерение напряжения на контактах. Если строка отсутствует, команда с браузера не дошла. Если
сразу появляется `[SAFETY]`, перестали поступать повторные команды удержания.
При нормальных логах проверьте VM относительно GND, SLP и сигналы на входах драйвера.
На малой скорости некоторые моторы не стартуют: кратко проверьте 100% с поднятыми
колёсами, только при питании, соответствующем номиналу моторов.

Повтор одной команды удержания теперь сохраняет PWM без промежуточного сброса.
При смене направления выходы сначала отключаются на 100 мкс. Диагностика читает
LEDC через 100 мкс после записи (два периода при 20 кГц), чтобы не показывать
значение предыдущего цикла. Это по-прежнему не измерение напряжения на GPIO.
Строка `[INPUT] Stop source=...` показывает источник команды остановки:
`pointerup`, `pointercancel`, `lostpointercapture`, `keyup`, `blur`, `hidden`,
`network-error`, `stop-button` или `pagehide`.

## Удержание и фиксация кнопки

По умолчанию удерживайте стрелку пальцем или левой кнопкой мыши. Отпускание
за пределами кнопки тоже останавливает моторы. Для измерений можно включить
**«Фиксировать направление после нажатия»**: одно нажатие запускает движение,
повторное на ту же стрелку или **СТОП** отключает его. Выбор другой стрелки меняет
направление. Смена режима останавливает моторы. Фиксация отключена по умолчанию.
В обоих режимах страница повторяет команды каждые 100 мс; закрытие/скрытие страницы,
потеря фокуса или связи останавливает движение. После ошибки связи нужно нажать
направление заново. После обновления прошивки обновите открытую страницу.

## Проверка направлений и совместимости с модулем Arduino.ua

Проверена [страница конкретного модуля](https://arduino.ua/prod3697-draiver-dvigatelei-dvyhkanalnii-drv8833).
Базовое управление соответствует таблице TI: IN1/IN2 = 1/0 — одно направление,
0/1 — противоположное, 0/0 — свободный выбег. Используется fast-decay PWM:
PWM/0 или 0/PWM. Частота остаётся 20 кГц. В таблице магазина есть повторяющиеся
комбинации входов с разными выходами; эталон — таблицы 1/2 даташита TI.
При отсутствии датчиков скорости это управление мощностью, не стабилизация оборотов.

На **100%** прошивка теперь отсоединяет GPIO от LEDC и устанавливает постоянные
HIGH/LOW; на **0%** устанавливает LOW. Для 1–99% подключает аппаратный PWM обратно.
Это позволяет отдельно проверить полную мощность, исключив генерацию PWM из теста.
Лог нормализован к 0–255 и отражает используемый выход (LEDC или GPIO).

В списке **«Моторы»** доступны **Оба / Только A / Только B**. При изменении выбора
движение останавливается; невыбранный мотор получает нулевую мощность.
Для диагностики с поднятыми колёсами проверьте на 100% сначала только A вперёд/назад,
затем только B вперёд/назад, затем оба. Между пробами нажимайте СТОП.
Минимальный PWM не повышается автоматически; при старте ниже 100% применяется
короткий стартовый импульс, описанный далее.

При текущей распиновке и `INVERT_A = INVERT_B = false` ожидаются уровни:

| Команда, оба мотора, 100% | GPIO21 (AIN1) | GPIO20 (AIN2) | GPIO10 (BIN1) | GPIO9 (BIN2) |
| --- | --- | --- | --- | --- |
| Вперёд | HIGH | LOW | HIGH | LOW |
| Назад | LOW | HIGH | LOW | HIGH |
| Влево | LOW | HIGH | HIGH | LOW |
| Вправо | HIGH | LOW | LOW | HIGH |
| Стоп | LOW | LOW | LOW | LOW |

HIGH соответствует примерно 3,3 В, LOW — примерно 0 В. Распиновка обновлена под фактическое подключение после перестановок при диагностике:
физический A теперь соответствует GPIO21/20, B — GPIO10/9. Если провода снова
меняются местами, необходимо согласовать константы A_IN1/A_IN2/B_IN1/B_IN2.
Вход STBY должен разрешать работу; программно он не управляется, так как GPIO
для него не задан. Сверяйте VCC/NC с маркировкой конкретной платы: в описании
магазина и отзывах отмечены расхождения; не подавайте питание на контакт NC.

Проверка логики без оборудования:

```sh
python3 test/check_motor_control.py
```

Тест компилирует фактические функции управления с имитацией периферии и проверяет
четыре направления, равную величину PWM, статические уровни на 100%, переходы
PWM/GPIO, выбор одного канала, остановку и отклонение некорректных команд.
Он не проверяет электрические уровни, ток или исправность подключённого драйвера.

Положение и подсветка стика показывают выбранное направление. Надпись **«Отправка команды…»**
появляется до ответа платы, **«Команда принята: …»** — после успешного HTTP-ответа.
Это подтверждает доставку команды, но не вращение: датчиков оборотов нет.
После изменения распиновки A/B не меняйте провода снова — UI согласован с
описанным фактическим подключением.

## Стартовый импульс для низкой мощности

Практическая проверка показала: после запуска на 100% мотор продолжает работать
на 40%, хотя с места на 40% не стартует. Для этого добавлен стартовый импульс:
при старте с нуля или смене направления мотор получает 100% на `START_BOOST_MS`
(180 мс по умолчанию), затем выбранную мощность. При запросе 0% мотор остаётся
выключенным; при 100% остаётся на полной мощности без таймера импульса.

Таймеры независимы для A/B. Команды удержания и изменение скорости в том же
направлении не продлевают импульс. Изменение скорости во время импульса задаёт
мощность после его завершения. Снижение скорости уже вращающегося мотора не
запускает импульс повторно. СТОП, неверная команда, обрыв Wi-Fi или таймаут отменяют
импульс; завершение таймера не включает остановленный мотор. Обслуживание таймеров
выполняется каждые 20 мс задачей защиты без блокирующего ожидания 180 мс.

На старте в логе могут быть значения 255 при выбранных 40% — это стартовый импульс,
а не ошибка. При завершении задача печатает `Startup pulse finished`.
Успешный ответ HTTP подтверждает приём команды, но не факт вращения мотора.
Для регулировки длительности измените `START_BOOST_MS`; значение 0 отключает импульс.
После загрузки обновите страницу, поднимите колёса и проверьте запуск вперёд/назад
на 40%. Физическая надёжность старта требует проверки: 180 мс — начальная настройка.
